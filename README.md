# 萤火虫反馈研究工作台 v3

GitHub Pages 网站： https://liziii148.github.io/aster-feedback/

研究流程已改为：广泛车型关键词检索 → 保留2026-10-15起语料及日期待核实项 → 逐篇读取正文 → 系统/功能候选筛选 → 人工复核 → 按功能与态度统计。

## 重要边界

“全部语料”表示导入的本次研究库，不代表小红书全平台全量。综合搜索可能遗漏帖子，日期筛选和平台返回范围也会影响结果。搜索卡片不会冒充已读取正文。视频画面、图片文字、音频尚未转写；只有这些媒体中的功能反馈可能漏筛，需人工查看原文。

当前浏览器中人工完成的登录不会传给GitHub Actions。仓库里的云端采集器仅尝试公开页面，不绕过验证、风控或登录。禁止把Cookie、账号密码、原始语料和用户资料提交到公开仓库。

## 新版复核

- 左侧分页列表、右侧原文和分类，帖子上下文不再分开找。
- 系统/功能候选、全部语料、已通过、已排除四个视图；日期未知可见。
- 功能与态度逐项绑定，不把“音乐赞赏、语音抱怨”做成错误交叉计数。
- 中性/操作说明可以复核，但不进入赞赏、抱怨、建议统计。
- 勾选多条后可批量排除、标系统候选、添加功能与态度、确认为2.1.0、通过完整分类。
- 批量标记后仍保持待核实；批量通过跳过分类未完成或只有卡片的记录。版本/日期未确认的原声不纳入本版本统计。
- J/K切换原声，A通过，X排除，U撤销；文本输入时不会触发快捷键。
- 切换原声时自动暂存当前分类草稿（当前页面内存），不需要每条点保存。
- 支持最近10次撤销；支持导入旧版JSON，导出完整进度后下次可恢复状态。

## 数据保存

默认仅页面内存。刷新前请导出完整进度；也可主动勾选“在本浏览器保存进度”。原声不会上传到网站服务器，不会自动提交GitHub，不会跨设备同步。

## 统计口径

默认仅统计已通过、系统/功能相关、已读取正文、发布日期在范围内且确认为Aster2.1.0的记录。其他版本及版本未知不混入2.1.0统计。同一帖子或评论在同一功能与态度内去重；跨功能或多种态度允许多计，因此分列相加可以超过去重原声总数。

编辑时间不替代发布时间；相对日期标记为估计，人工可修正。摄像头硬件故障等现象保留在“升级后其他问题（归因待核实）”，不据时间先后断定因果。

## GitHub 手动采集

Actions → 广泛检索与系统功能筛选（公开页面） → Run workflow。

配置位于collector/config.json：默认firefly萤火虫、蔚来萤火虫、萤火虫汽车3个广泛关键词；每词最多12次滚动，每轮最多读取150篇，间隔4秒。这些是执行上限，不能解读成全量；report.json记录停止位置、失败和限额。云端任务没有本聊天浏览器的登录态，未保证能读到搜索结果。

下载运行产物后：corpus.json包含已尝试获取的日期范围内语料，system-candidates.json为规则筛选子集，report.json为覆盖报告。本阶段云端任务收集帖子正文，不采评论，报告明确标记commentsCollected=0。前次两条测试帖的评论可以作为独立数据文件导入并去重。

`node site/model.test.cjs` 检验功能-态度对应、日期/版本/状态排除、中性说明、去重、导入和安全校验。
